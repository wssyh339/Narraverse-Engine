# 专业创作工作室设计

## 目标

把当前项目从多个独立管理页升级为一个围绕“当前章节上下文”运行的长篇小说创作工作室。能力参考成熟小说编辑器的工作流，但 UI、文案和实现保持独立，不实现会员、计费、云同步或自动发布。

## 调研结论

目标编辑器实际采用重型单页工作区：

- 页面入口加载统一 `EditorWorkspace`，而不是把正文、设定、大纲和笔记拆成互不关联的产品。
- 使用 Zustand 管理工作台状态，正文编辑器基于 CodeMirror，预览使用 Markdown 渲染。
- 采用可调整宽度的左侧目录、中央创作区、右侧 AI 助手。
- 本地修改优先保存；AI 修改先进入审批和回滚流程。
- 设定增量更新提供预览、应用、恢复和重新投影能力。

本项目继续使用既定 React、Ant Design、Zustand、`@uiw/react-md-editor` 和 FastAPI 技术栈，不引入新的编辑器框架。

## 信息架构

项目工作室顶部包含五个一级工作区：

1. **作品**：题材、简介、风格、Story Bible 和创作约束。
2. **正文**：卷章目录、正文编辑器、写作工具、版本和 AI 助手。
3. **设定**：角色、地点、组织、物件、规则、伏笔与图谱。
4. **大纲**：总纲、卷纲和章纲。
5. **笔记**：目录化笔记和灵感卡，可作为 AI 上下文引用。

正文工作区为三栏：

- 左栏：分卷/章节目录、资源切换、伏笔提醒。
- 中栏：章节元数据、编辑器工具栏、正文编辑/预览/Diff。
- 右栏：AI 快捷工具、上下文引用、提案审批、版本历史。

## 核心交互

### 正文保存

编辑器输入后进入 dirty 状态，停止输入后自动保存；强制保存支持 `Ctrl/Cmd + S`。保存正文前自动创建版本快照，避免误覆盖。

### AI 编辑

开篇、续写、优化、审稿、润色、重写和灵感均先生成 `editor_proposal`。提案包含原文、建议稿和 diff。用户可以应用或拒绝；应用前再次保存快照。

### 目录与回收站

章节支持手动创建、重命名、移动分卷、按 `sort_order` 排序、软删除、恢复。回收站不参与正文生成和导出。

### 设定更新

Agent 抽取的新角色、实体、世界事实和伏笔保持候选状态，必须由用户确认后写入正式设定。用户手动设定不会被自动覆盖。

### 本地备份

项目可导出完整 JSON 备份，包含作品资料、章节、分卷、笔记、设定、伏笔和版本元数据。云同步和在线发布仍不实现。

## 视觉方向

采用安静、专业、适合长时间写作的工作台风格：

- 主色为墨绿，辅助色使用琥珀和中性灰。
- 页面区块使用分隔线和背景层级，不堆叠装饰性卡片。
- 编辑器是第一视觉重点，章节目录和 AI 助手可折叠。
- 图标按钮提供 tooltip；密集工具栏使用图标和短标签。
- 支持亮暗主题和专注模式。

## 验收

- 用户可以从 Dashboard 创建项目并进入统一工作室。
- 可完成分卷/章节创建、编辑、排序、删除和恢复。
- 正文自动保存、智能排版、查找替换、高频词和历史恢复可用。
- AI 工具生成提案，未确认时不修改正文，确认后可回滚。
- 作品、设定、大纲和笔记在项目工作室内可访问并共享上下文。
- 后端测试、前端测试、生产构建和真实浏览器端到端流程全部通过。
