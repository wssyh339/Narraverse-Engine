## 第一轮测试后的修改意见

1. 本地预览路径仍不会自然生成 decision/scores，需要服务层为 local_preview 补默认裁决与评分，否则真实模型可输出字段，但本地预览报告会显示为空。
2. 若章节阶段一次生成100章，当前本地预览标题和核心事件重复度偏高，应在 fallback 章纲生成里按10章窗口加入节奏段、阶段目标和卷内序号变化。
3. 候选门槛已生效，但角色/设定的候选策略报告应保留 trigger_gate，方便前端解释为什么没有生成候选。
4. 后续如接真实 LLM，应要求每个专席至少输出 decision 和 scores；连续性审计的 blocking_items 应进入确认门禁。
## 二次修改与复测结论

第一轮压测暴露了两个问题：

1. 报告脚本最初读取 `run_phase` 返回结构时误读了顶层 `result`，真实章节结果位于 `phase_run.result.chapter_outlines`，导致报告误判章节数量为 0。
2. `local_preview=True` 时服务层虽然保留了新增字段，但没有为 `decision` 和 `scores` 提供默认值，导致离线预览无法直观看到裁决与评分。

已完成的二次修改：

1. 在 `outline_debate_service.py` 中加入 `_default_agent_decision`、`_default_agent_audit_status` 和 `_default_agent_scores`，仅用于本地预览路径，不覆盖真实模型输出。
2. 修正压测脚本读取路径，统一从 `phase_run.result`、`phase_run.turns`、`phase_run.candidate_policy` 读取测试证据。
3. 保留 `trigger_gate` 到 `candidate_policy.character_gap` 和 `candidate_policy.setting_gap`，方便前端解释为什么角色/设定候选没有被生成。

## 新的后续修改意见

1. 建议下一步让确认门禁读取 `blocking_items`：只要连续性审计输出 `severity=blocking`，前端确认按钮应展示阻塞原因，并要求重新讨论或用户显式覆盖。
2. 建议把 `scores` 聚合成阶段级仪表盘：总纲、卷纲、章纲分别显示卖点、结构、角色、设定、连续性最低分。
3. 建议把 `trigger_gate.reason` 在前端候选区展示出来：用户会清楚知道为什么某个角色/设定没有被自动入候选。
4. 建议后续补一轮远程 LLM 小样本评估：每类题材先跑 1 个 book 阶段和 1 个 chapters 小范围阶段，观察真实模型是否稳定遵守 JSON 输出契约。
5. 建议章节 fallback 继续增强：目前本地预览能生成 100 个章纲，但标题/事件仍偏模板化；可按每 10 章窗口注入阶段目标、反转、代价和伏笔回收，以便离线预览更接近真实创作节奏。
