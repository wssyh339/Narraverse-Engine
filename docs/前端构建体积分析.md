# 前端构建体积分析

日期：2026-06-05

## 原始警告

Vite 生产构建曾输出：

```text
dist/assets/index-DTmZ1Ocr.js   3,381.46 kB │ gzip: 1,108.20 kB

(!) Some chunks are larger than 500 kB after minification.
```

这表示前端把大部分页面与重型依赖打进了同一个入口 chunk，首屏需要下载和解析约 `3.38 MB` 的 JS。

## 体积来源

使用 sourcemap 按依赖来源统计，主要来源为：

| 来源 | 原始源码体积约 | 原因 |
| --- | ---: | --- |
| `echarts` + `zrender` | `4.1 MB` | 页面使用 `import * as echarts from "echarts"`，拉入完整图表库 |
| `antd` / `rc-*` | `1.1 MB+` | 多页面共享大量中后台组件 |
| `@uiw/react-md-editor` / `refractor` | `1 MB+` | Markdown 编辑器内置语法高亮语言包 |
| Markdown/HTML 解析链 | `500 KB+` | `react-markdown`、`remark-gfm`、`parse5`、`unified` 等 |
| 业务页面源码 | `128 KB` 左右 | 不是主要问题 |

## 已完成修复

1. 路由级懒加载：`src/App.tsx` 使用 `React.lazy + Suspense`，Dashboard 首屏不再加载所有工作台页面。
2. ECharts 按需导入：`GraphPage` 和 `AgentsPage` 只注册 `GraphChart`、`TooltipComponent`、`CanvasRenderer`。
3. 轻量 Markdown 编辑：用 Ant Design `Input.TextArea` + `react-markdown` 预览替代 `@uiw/react-md-editor`，移除高亮语言包进入构建产物。
4. Vite 分包：按 charts、markdown、router、query、http、lucide、react 拆分 vendor chunk。

## 修复后结果

当前生产构建最大 chunk：

```text
dist/assets/index-CslEj4z7.js       494.81 kB │ gzip: 158.61 kB
dist/assets/vendor-charts-*.js      458.61 kB │ gzip: 154.34 kB
dist/assets/vendor-markdown-core*.js 153.98 kB │ gzip: 46.45 kB
dist/assets/vendor-react*.js        142.44 kB │ gzip: 45.84 kB
```

Vite 构建已不再出现超过 `500 KB` 的 chunk 警告。

## 后续可继续优化

- 如果图谱页首开仍觉得慢，可进一步把 ECharts 的力导向图封装为局部动态组件，只在图谱容器进入视口后加载。
- 如果后续恢复 Monaco 或更强 Markdown 编辑器，应只在工作台/笔记页动态加载，不放入应用入口。
- Ant Design 仍是主要共享依赖，若追求更极致首屏，可按页面改为更细粒度的 `antd/es/*` 导入或替换部分轻量组件。
